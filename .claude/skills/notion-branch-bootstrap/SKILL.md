# Notion 이슈 기반 브랜치 부트스트랩

## 목적
Notion 이슈 ID를 받아 구현 시작 전 준비 작업을 자동화한다.

## 절차

### 1. 이슈 조회
- Notion MCP의 `notion-search`로 `[BE]작업` DB에서 해당 이슈 ID 검색
- 이슈를 찾으면 `notion-fetch`로 상세 내용 조회
- 이슈 제목, 상태, 설명, 관련 스펙 링크 확인

### 2. 이슈 분석 출력
```
📋 이슈: IEUM-BE-{번호} - {제목}
📌 상태: {상태}
📝 설명 요약: {핵심 내용 3줄 이내}
🔗 관련 스펙: {링크가 있으면 표시}
```

### 3. 브랜치명 제안
- 이슈 제목/내용에서 타입 추론:
  - 새 기능 → `feat/IEUM-BE-{번호}`
  - 버그 수정 → `fix/IEUM-BE-{번호}`
  - 설정/인프라 → `chore/IEUM-BE-{번호}`
  - 코드 개선 → `refactor/IEUM-BE-{번호}`
- 브랜치명은 영어 소문자 + 하이픈만 사용

### 4. 영향 범위 분석
- 관련 모듈 식별: api, auth, workflow-core, ai, integration, common
- 수정/생성 예상 파일 목록
- 의존 모듈 체인 확인 (순환 참조 위험 평가)

### 5. 커밋 계획 제안
- 구현 단위를 커밋 단위로 분리하여 표로 정리:

```
| Step | 커밋 메시지 | 주요 파일 | 예상 작업량 |
|------|-----------|----------|-----------|
| 1    | feat: ... | ...      | ...       |
| 2    | feat: ... | ...      | ...       |
```

- feature 브랜치 수명 최대 3일 기준으로 작업량 조절
- 3일 초과 예상 시 이슈 분할 제안

### 6. 실행 안내
```
💡 브랜치 생성 명령어 (직접 실행):
git checkout develop
git pull origin develop
git checkout -b {브랜치명}
```

## 규칙
- **git 명령은 절대 실행하지 않음** — 안내만 출력
- Notion 검색이 실패하면 이슈 ID를 다시 확인하도록 안내
- 이슈 내용이 불명확하면 보충이 필요한 부분을 지적
