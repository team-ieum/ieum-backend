# PR 준비 체크리스트

## 목적
PR 생성 전 필요한 모든 점검을 수행하고, PR 설명 초안과 Squash Merge 커밋 메시지를 생성한다.

## 실행 절차

### Step 1: 빌드 검증
```bash
./gradlew build
```
- 빌드 성공 여부 확인
- 컴파일 에러 리포트
- 테스트 실패 리포트

### Step 2: 통합 코드 품질 점검
- `verify-implementation` 스킬 실행 (등록된 모든 verify 스킬 순차 실행)
- 결과 요약: PASS / WARN / FAIL 항목 정리

### Step 3: 추가 점검
- 미사용 import 체크 (IDE 수준)
- TODO / FIXME 잔여 확인 — 의도적인 것인지 사용자에게 확인
- 하드코딩된 값 체크 (URL, 포트, 시크릿 등)
- .env 파일에 새로 추가해야 할 환경변수 확인

### Step 4: Notion 이슈 동기화 확인
- Notion MCP로 해당 이슈 페이지 조회
- 이슈 내용과 실제 구현 내용 비교:
  - 이슈에 명시된 작업이 모두 구현되었는가
  - 구현했지만 이슈에 없는 추가 작업이 있는가
- 불일치 발견 시:
  ```
  ⚠️ Notion 이슈 동기화 필요:
  - 이슈에 있지만 미구현: {항목}
  - 구현했지만 이슈에 미기재: {항목}
  → Notion 페이지 업데이트를 제안합니다.
  ```

### Step 5: PR 설명 초안 생성

```markdown
## 📋 관련 이슈
- [IEUM-BE-{번호}: {제목}]({Notion 링크})

## 📝 작업 내용
{구현 내용 요약 — bullet point 3~5개}

## 🔍 주요 변경 사항
| 모듈 | 변경 내용 |
|------|----------|
| {모듈명} | {변경 요약} |

## 🧪 테스트
- {테스트 현황}

## ✅ 체크리스트
- [ ] 빌드 성공 (`./gradlew build`)
- [ ] 테스트 통과
- [ ] Notion 이슈 내용 업데이트 완료
- [ ] Swagger 문서 확인
- [ ] 보안 민감 데이터 노출 없음
- [ ] DB 마이그레이션 스크립트 포함 (해당 시)
```

### Step 6: Squash Merge 커밋 메시지 제안
```
[{type}] {기능명} (#{PR번호})

- {주요 변경사항 1}
- {주요 변경사항 2}
- {주요 변경사항 3}
```

## 최종 출력 형식
```
🔍 PR 준비 점검 결과

1. 빌드: ✅ PASS / ❌ FAIL
2. 코드 품질: ✅ {N}개 PASS / ⚠️ {N}개 WARN / ❌ {N}개 FAIL
3. Notion 동기화: ✅ 일치 / ⚠️ 불일치 ({N}건)
4. 추가 점검: ✅ 이상 없음 / ⚠️ {항목}

📋 PR 설명 초안이 준비되었습니다.
💡 git 명령어 (직접 실행):
  git push origin {브랜치명}
```

## 규칙
- git 명령은 안내만 하고 실행하지 않음
- PR은 반드시 Squash Merge
- feature 브랜치 수명 최대 3일 초과 시 경고 출력
